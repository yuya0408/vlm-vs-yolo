# ADR-0002: VLMのプロンプトを3水準振り、YOLOの閾値と同じtune/testの手順で選んで、結論が変わるかを確かめる

- Status: Accepted
- Date: 2026-08-31

## 結論（Summary）

- VLMのプロンプトを3水準（`concise`・`deliberate`・`calibrated`）で実行し、tune 120枚のmicro-F1が最大の水準を選んで、test 180枚でYOLO（conf=0.075）と比べる（決定）。
- 判定の規則は実行の前に書いた（2026-08-31、実行は2026-09-05）。ただし、規則を決めた時点で`concise`の結果とYOLOとの比較は見ていた。
- 結果は`concise`のままで、testでYOLOとの差は検出できず（p=0.42）、3水準のばらつきはmacro-F1で0.46pt。規則により結論は変えない（A1）。
- 3水準の比較はtest 180枚にそろえ、全体の検定（Friedman）を足した（A2）。

## 背景と問い（Context and Problem Statement）

[ADR-0001](0001-threshold-operating-point.md)でYOLOの閾値を詰めたのに対し、VLMは1つのプロンプト（`concise`）・temperature 0・1回の実行のままだった。「片方だけ既定の設定で比べている」という批判は、向きを変えるとそのままこの比較に当たる。精度は差を検出できないところまで詰まっているので、プロンプトを変えれば結論がどちらに転ぶかは前もって分からない。

ただし、プロンプトは閾値のように全点を走査できない。閾値は[0,1]の1次元で、1点あたりの費用が0（推論後のフィルタ）だが、プロンプトには次元も境界も無く、1点試すたびに300枚の再推論（1水準あたり約250〜310円）が要る。問いは、走査できない側で、結論が反転しないことを何で確かめるか、である。

## 判断の基準（Decision Drivers）

- 選び方をYOLOの閾値と同じ手順（同じtune/testの分割で、tuneのmicro-F1が最大）にそろえる。
- 結論を書き換える条件を、実行の前に文章で残す。
- 1水準あたり約250〜310円の費用で、水準の数を抑える。

## 検討した案（Considered Options）

| 案 | 採否 | 理由 |
| --- | --- | --- |
| プロンプトを振らない | 却下 | YOLOの閾値だけを詰めた比較になり、ADR-0001で避けた非対称が逆向きに残る |
| プロンプトの空間を走査する | 不可 | 次元も境界も無く、「全部試した」という状態が無い |
| **代表的な3水準を振り、tuneで選んでtestで比べる** | **採用** | 最も一般的な改善の手（根拠を先に書かせる）と、観察した過剰な主張・`uncertain`の少なさがプロンプトの産物かを見る水準を入れる |
| 全300枚で最良の水準を選んで報告する | 却下 | テストで選んでテストで報告することになる。YOLOの手順ともそろわない |

## 決定（Decision Outcome）

水準は次の3つ。

| 水準 | 何を変えたか | 何を確かめるか |
| --- | --- | --- |
| `concise` | 本編のプロンプト（基準） | 今の値 |
| `deliberate` | 項目ごとに根拠を先に書かせてから判定する | 考えさせれば精度が上がるか |
| `calibrated` | チェックリスト由来の過剰な主張を抑え、`uncertain`を使う基準を明示する | 偽陽性と`uncertain`率0.31%がプロンプトの産物か |

ADR-0001と同じ分割（seed 42、tune 120枚・test 180枚）で、tuneのmicro-F1が最大の水準を選び、testでYOLO（conf=0.075）と画像単位のペア差CIとMcNemarで比べる。結果は次のように読む（実行の前に書いた規則の要約。原文は[REPORT §2b](../../report/REPORT.md#2b-vlm-側のプロンプト感度3-水準実行済み結論不変)）。

| 結果 | 読み方 |
| --- | --- |
| 選んだ水準でもtestでYOLOとの差が有意でなく、水準間のばらつきがYOLOの閾値の振れ幅（macro-F1 0.921〜0.945の2.4pt）と同程度以内 | 結論は変えない。「VLM側も3水準で確かめた」と書き足す |
| 選んだ水準で、VLMがtestで有意に上 | 「精度では差を検出できない」という結論と、選び方の規則を書き換える |
| どちらでも、ばらつきが2.4ptを大きく超える | 「VLMの精度はプロンプトで数pt動く」を限界に入れる |

### 確かめ方（Confirmation）

- 規則はコミット`c2a2192`（2026-08-31）でREPORTに書き、実行（2026-09-05）の後も文面を変えていない。
- `python -m src.analysis.prompt_sensitivity`（コマンドはREPORT §2b）が`results/prompt_sensitivity.json`を作る。

## 影響（Consequences）

- 得るもの：VLM側の設定も動かしたうえで、結論が反転しないことを示せる。
- 失うもの：3水準の実行で約570円（思考を含まない記録）。
- 残る穴：
  - 規則を決めた時点で`concise`の結果を見ていた。`calibrated`はその誤りを見て作った水準である。
  - 3水準はプロンプトの空間の探索ではない。ほかのプロンプトでは変わりうる。
  - temperatureは0に固定した（Gemini 3系の公式は既定の1.0を勧める）。温度による変化は確かめていない。

### 妥当性への脅威（Threats to Validity）

| 懸念 | 対処 | 残る影響 |
| --- | --- | --- |
| 規則を決めた時点で`concise`の結果とYOLOとの比較を見ていたので、規則が`concise`に合わせて作られうる | 見ていたことを規則の前書きに書いた。`deliberate`・`calibrated`の結果は規則の後に出た | `concise`の結果を知ったうえでの規則である |
| `calibrated`は`concise`の誤りを見て作ったので、この評価セットに合わせた水準になりうる | 選定はtuneで行い、testで比べる | 同じ300枚の誤りを見て作った水準である |
| 3水準は空間の一部しか見ない | 何を確かめる水準かを決定の表に書いた | ほかのプロンプトでは変わりうる |
| 水準ごとに比べる枚数がそろっていないと、点推定の差が見かけの差になりうる | testの180枚にそろえて比べ直した（A2） | なし |
| 水準のペアごとの検定だけでは、3水準全体の差を見落としうる | 画像単位の全体の検定を足した（A2） | なし |

### A1 追記（2026-09-05）：規則どおりに読む

（決定日 2026-09-05）

tuneのmicro-F1が最大の水準は`concise`だった。testでのYOLOとの差はmacro-F1で+1.69pt [−2.33, +3.56]、McNemar p=0.42で有意でない。水準間のばらつき（最大−最小、全300枚）はmacro-F1で0.46pt（`calibrated` 0.9589 → `deliberate` 0.9635）で、YOLOの閾値の振れ幅2.4ptより小さい。規則の1行目に当たり、結論は変えない。

### A2 追記（2026-09-05）：比べる枚数をそろえ、全体の検定を足す

（決定日 2026-09-05）

最初の表は、`concise`をtestの180枚、`deliberate`・`calibrated`を全300枚で並べていて、点推定の大小が枚数の違いによる見かけの差かどうかを分けられなかった。3水準ともtestの180枚にそろえて計算し直した。
また、水準の差は`concise`を基準にしたペアごとのMcNemar（項目単位）を2回行っただけで、`deliberate`と`calibrated`の間は見ておらず、項目単位の検定は画像の中の相関を無視していた（ADR-0001のA1に反する）。画像単位のitem accuracyで、全体の検定を足した。天井に近く正規性の仮定が成り立たないので、Friedman検定（χ²=3.71、p=0.16）を主にし、反復測定ANOVA（F=1.20、p=0.30）を並べた。結果を見た後の補完で、判定は変わらない。
