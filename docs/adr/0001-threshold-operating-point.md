# ADR-0001: YOLOの閾値を全点で走査し、VLMのスコアを使わない基準（micro-F1とitem accuracyの最大）で操作点を選ぶ

- Status: Accepted
- Date: 2026-06-29

## 結論（Summary）

- YOLOは conf=0.001 で1回推論し、後処理で閾値を全点走査する。操作点は micro-F1 と item accuracy が最大の閾値で、どちらも 0.075 だった（決定）。
- 選定にVLMの値は使わない。既定の 0.25 は比べる点として残す（決定）。
- モデル間の差は、画像単位のペア差ブートストラップCIを主な推論、項目単位のMcNemarを補助にする（A1）。許す差を置かないので、読み方は「VLMが有意に上」か「差を検出できなかった」の2つで、同等とは書かない（決定）。
- 差を検出できない範囲は、主な推論で読んでグリッド上の conf 0.05〜0.10（A3）。0.005刻みでも結論は変わらない（A4）。
- この決定は、既定の閾値でVLMが有意に上回った結果（p=0.004）を見た後に行った。

## 背景と問い（Context and Problem Statement）

COCO val2017の300枚で、YOLO（`yolo26x`）とVLM（`gemini-3.5-flash`）の有無判定を比べた。YOLOをUltralyticsの既定 conf=0.25 のまま比べると、VLMがmacro-F1で+5.5pt上回り、McNemarでp=0.004だった。

一方でVLMはプロンプトを書いて使い、YOLOは閾値を既定値のまま使っていた。片方だけ設定を詰めていない比較で出た差は、モデルの差なのか設定の差なのかを分けられない。既定の閾値での誤り88件のうち77件は見逃し（在るのに検出しない）で、閾値が高すぎることを示していた。

問いは、YOLOの閾値をどう選べば、選び方そのものがVLMとの比較に有利・不利を持ち込まないか、である。制約は、この決定が既定値の結果を見た後になることと、別の評価データを持たないこと。

## 判断の基準（Decision Drivers）

- 選定にVLMの値を使わない（使えば、テストで選んでテストで報告することになる）。
- 検出器で一般的な操作点の選び方に従い、この比較のために作った基準にしない。
- 1点あたりの費用が0なので、点を選ぶ前に全点を見せられる（閾値は推論後のフィルタで、再推論が要らない）。
- 有無判定では、項目が画像の中で独立でない（1画像に5〜10項目）。

## 検討した案（Considered Options）

| 案 | 採否 | 理由 |
| --- | --- | --- |
| 既定の conf=0.25 のまま比べる | 却下（比べる点としては残す） | 片方だけ既定値の比較になる。差の大半がYOLOの見逃しから来ていた |
| macro-F1が最大の閾値（0.01） | 却下 | 有無判定では座標の罰（IoU）が無いので、閾値を下げるほど再現率に振れる退化点になる。偽陽性が増え、項目単位ではVLMが再び有意（p=0.003） |
| **micro-F1とitem accuracyが最大の閾値** | **採用** | 検出器のF1最大点を操作点にする慣行に当たる。2つの指標がともに0.075で最大になり、丸めの余地が無い |
| VLMとの差が最小になる閾値 | 却下 | 選定にVLMの値を使う。結論を先に決めて点を選ぶことになる |
| 120枚（tune）で選び、180枚（test）だけで報告する | 確かめとして実施、主にはしない | 分割は全体の集計を見た後に行ったので、リークの無い分割とは言えない。tuneで選んでも0.075で、testでもp=0.42だった |

## 決定（Decision Outcome）

YOLOを conf=0.001 で1回推論して全検出を保存し（`results/yolo_raw_detections.json`）、0.01〜0.75の閾値で有無を作り直す。操作点は、全300枚で micro-F1 と item accuracy が最大の閾値とする。既定の0.25は、比べる点として結果に残す。

モデル間の差は、操作点と各閾値で次のように読む。

| 結果 | 読み方 |
| --- | --- |
| macro-F1・micro-F1・item accuracyのどれかで、ペア差95%CIが0を含まない（VLM−YOLO > 0） | VLMが有意に上 |
| 3指標ともペア差95%CIが0を含む | 差を検出できなかった（同等とは書かない） |
| McNemarのp | 補助の確かめとして並べる。判定には使わない（A1） |

### 確かめ方（Confirmation）

- `python -m src.analysis.yolo_threshold sweep --raw results/yolo_raw_detections.json --eval-set data/eval_set.json` が `results/yolo_threshold.json` を作る（`tests/test_yolo_threshold.py`）。
- `python -m src.analysis.plots` が閾値ごとのペア差CIを `results/threshold_paired_diff.json` に書き、図の印をその判定で塗る。
- `locks/analysis.lock` の版で、上の2つがコミット済みのファイルとバイト単位で一致することを確かめた（2026-11-23）。

## 影響（Consequences）

- 得るもの：片方だけ既定値の比較を避け、閾値を変えると有意差が出たり消えたりすることを、図1枚で示せる。
- 失うもの：操作点は既定値の結果を見た後に、同じ300枚で選んで報告している。
- 残る穴：
  - 閾値の効果を、別のデータで確かめていない。
  - 差を検出できない範囲は0.05〜0.10に限られ、0.01・0.02では再びVLMが有意になる。「閾値によらず差が無い」とは言えない。
  - macro-F1のCIは、正例1件のカテゴリの出入りで点差の周りに対称にならない。

### 妥当性への脅威（Threats to Validity）

| 懸念 | 対処 | 残る影響 |
| --- | --- | --- |
| 同じ300枚で選んで報告するので、操作点に有利な偏りが入りうる | 選定の式にVLMを使わない。tune 120枚で選んでも0.075で、test 180枚でもp=0.42 | 分割も全体の集計を見た後に行った。別のデータでの確認は無い |
| 3つの基準（慣行のF1最大点・tuneでの最大・全体での最大）の一致を、独立な裏付けと読みうる | 同じ300枚から計算していて独立ではないと書いた（A2） | なし |
| 項目は画像の中で独立でないので、項目単位の検定は有意に出すぎうる | 主な推論を画像単位のペア差CIにした（A1） | McNemarは項目単位のまま補助に残る |
| グリッドが荒く、操作点が刻みの選び方の産物でありうる | 0.005刻みで走査し直した（A4） | なし |
| macro-F1は正例1件のカテゴリが1件の正誤で1.28pt動き、差を大きく見せうる | 正例の数で絞った内訳を出し、micro-F1・item accuracyと合わせて読む | macro-F1の差3.2ptのうち2.6ptは正例1件の2カテゴリから来ている |

### A1 追記（2026-08-29）：主な推論を画像単位のペア差CIにする

（決定日 2026-08-29）

項目（画像×カテゴリ、2,281件）は同じ画像の中で独立でない。ブートストラップのCIは最初から画像単位だったが、McNemarと誤りの要因の回帰は2,281項目を独立に扱っていて、扱いがそろっていなかった。
また、2つのモデルの周辺CIが重なることは、差が有意でないことを意味しない。そこで、同じリサンプルの添字でVLM−YOLOの差の分布を作る画像単位のペア差CIを主な推論にし、McNemarは補助の確かめにした。回帰は画像単位のクラスタ頑健SEにした。
既定値の結果も操作点の結果も見た後の変更なので、結果の後の補完に当たる。0.075で差を検出できず、0.25でVLMが有意に上という判定は、どちらの推論でも同じだった。

### A2 追記（2026-10-31）：3つの基準は独立ではない

（決定日 2026-10-31）

最初の記述は、操作点を「VLMに依らない3つの独立な基準が一致する点」としていた。3つは同じ300枚から計算しているので独立ではなく、閾値を見直すきっかけも既定値での結果だったと書き直した。規則も値も変えていない。

### A3 追記（2026-11-17）：差を検出できない範囲を主な推論で読む

（決定日 2026-11-17）

「差を検出できない範囲」と図の印は、補助のはずのMcNemarから描いていて、0.025〜0.15だった。主な推論（ペア差CI、3指標）で読み直すと、0.025ではmicro-F1、0.125・0.15ではmacro-F1のCIが0を含まず、範囲は0.05〜0.10になる。A1で決めた主と補助の関係に、範囲の書き方を合わせた。
同時に、tune/test分割を「リークの無い分割」と呼んでいたのを、「全体の集計を見た後の分割」と書き直した。操作点0.075での判定は変わらない。

### A4 追記（2026-11-17）：0.005刻みで走査し直す

（決定日 2026-11-17）

グリッドの刻みが荒く、操作点が刻みの産物かどうかを確かめるため、0.01〜0.25を0.005刻みで走査した（`sweep --step 0.005`、`results/yolo_threshold_fine.json`）。micro-F1の最大は全300枚でもtuneの120枚でも0.08（全300枚で0.956）で、0.075との差は0.2ptだった。0.08でも差は検出できない。規則どおりに読んだ結果で、操作点は0.075のままにした。
